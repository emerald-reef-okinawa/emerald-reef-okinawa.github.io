# FormSubmit 予約メール → Google カレンダー 自動登録＋予約メール下書き (GAS)

EMERALD REEF OKINAWA の予約フォーム（FormSubmit）からの通知メールを定期チェックし、
本文の表から予約内容を抽出して、

1. Google カレンダー（`予約状況`）に予定を自動登録
2. お客様あての **「受付メール」「予約確定メール」の Gmail 下書き** を自動作成

します。さらに、

3. **予約日の前日に「リマインドメール」を自動送信**（メール内の「参加を確認する」
   ボタンを押すと、カレンダー予定が「確認済み（✅・緑）」に変わる）

機能もあります。

## 動作仕様

- **対象**: `submissions@formsubmit.co` からのメールで、**件名に「予約」を含むもの**だけ
  - 件名が `【○○問い合わせ】…` のように「予約」を含まない場合はカレンダー登録しない
- **登録先**: `予約状況` という名前のカレンダー
- **抽出項目**: ご希望日 / ご希望時間 / お名前 / 参加人数 ほか本文の表すべて
- **予定の時間**:
  - ご希望時間あり → その時刻から **4時間**
  - ご希望時間なし（「相談したい」等）→ **11:00 から 4時間**（11:00〜15:00）
- **二重登録防止**: 処理済みメールに `カレンダー登録済み` ラベルを付与（次回スキップ）

### 予約メールの下書き自動作成

- 1 件の予約につき **2 通の下書き** を作成します
  - **① 受付メール**: そのまま送信できます（「リクエストを受け付けました」の連絡）
  - **② 予約確定メール**: `【　】` の欄（集合時間・料金・送迎場所・決済リンク）を
    手入力してから送信します
- **言語の自動判定**: お名前に日本語（かな・漢字）が含まれれば日本語、なければ英語の下書き
- 文面は [`mail-templates.md`](./mail-templates.md) を参照。変更したい場合は
  `Code.gs` の `buildAckJa_` / `buildConfirmJa_` / `buildAckEn_` / `buildConfirmEn_` を編集
- 下書き作成を止めたい場合は `Code.gs` の `CONFIG.CREATE_DRAFTS` を `false` に
- 作成された下書きは Gmail の「下書き」フォルダに入ります（自動送信はしません）

### 前日リマインドメール＋確認ボタン

- 毎日 1 回（既定: 朝 10 時台）、**翌日が予約日の予定** を探してお客様へ自動送信します
  （受付・確定とは違い、こちらは **自動送信** です）
- メール内の「**参加を確認する**」ボタンを押すと、その予約のカレンダー予定が
  **タイトル先頭に「✅」・色が緑・説明欄に「お客様確認済み: 日時」** に変わります
- 言語はお名前で自動判定（日本語/英語）。文面は [`mail-templates.md`](./mail-templates.md) 参照
- 二重送信防止：送信した予定の説明欄に `[リマインド送信済み]` を追記
- 止めたい場合は `CONFIG.SEND_REMINDERS` を `false` に
- ⚠ **この機能を使うには「ウェブアプリのデプロイ」が必要** です（下記セットアップ参照）

## セットアップ手順

1. **スクリプト作成**
   - <https://script.google.com> →「新しいプロジェクト」
   - `Code.gs` の中身を全部コピーして貼り付け

2. **タイムゾーン確認**（重要）
   - 左の歯車「プロジェクトの設定」→ タイムゾーンが **(GMT+09:00) 東京** になっているか確認
   - 違う場合は東京に変更（日時のズレ防止）

3. **設定を確認**（`Code.gs` の `CONFIG`）
   - `CALENDAR_NAME` … `予約状況`（この名前のカレンダーに自動で登録。ID 不要）
   - 所要時間や開始時刻を変えたい場合は `DURATION_HOURS` / `DEFAULT_START_HOUR`
   - `CONFIRM_SECRET` … **推測されにくい文字列に必ず変更**（確認ボタンの改ざん防止用）

4. **動作テスト**
   - 予約メールが受信トレイにある状態で、関数 `processMailToCalendar` を選んで「実行」
   - 初回は Google の認可画面が出るので承認
   - カレンダーに予定が入り、受付・確定の下書きが Gmail に作られるか確認

5. **自動実行を有効化（メール → カレンダー）**
   - 関数 `createTrigger` を 1 度だけ「実行」 → 以降 5 分おきに自動実行

6. **ウェブアプリを公開（前日リマインドの「確認ボタン」用 ⚠必須）**
   - 右上「デプロイ」→「新しいデプロイ」→ 種類「ウェブアプリ」
   - **次のユーザーとして実行**：自分（自分のアカウント）
   - **アクセスできるユーザー**：**全員**（お客様はログインせずにボタンを押すため）
   - 「デプロイ」→ 認可を承認 → 表示される **ウェブアプリ URL**（`.../exec`）を控える
   - ⚠ **控えた `/exec` URL を `Code.gs` の `CONFIG.WEBAPP_URL` に貼る**（重要）
     - これを設定しないと、エディタから手動実行したときのリマインドメールのボタンが
       **開発用(/dev)URL** になり、お客様側で「現在、ファイルを開くことができません」と
       なって開けません。`/exec` を固定しておけば手動・トリガーどちらでも正しく動きます。
   - ※コードを更新したら「デプロイの管理」→ 既存デプロイを編集して更新する
     （URL を変えたくない場合。新規デプロイすると URL が変わります）

7. **前日リマインドを有効化**
   - 関数 `createReminderTrigger` を 1 度だけ「実行」 → 毎日 朝 10 時台に自動送信
   - テスト：翌日の日付でテスト予約を 1 件カレンダーに作り、`processReminders` を手動実行
     → 自分宛にリマインドが届き、ボタンを押すと予定が ✅・緑になることを確認

## あそびゅー（asoview）予約の自動登録

自社フォームに加えて、**あそびゅー！の「予約が確定しました」メール**も同じ `予約状況`
カレンダーに自動登録します（`processMailToCalendar` が毎回あわせて処理）。

- **対象**: `mailsender@asoview.com` からの、**件名に「予約が確定」を含む**メールだけ
  （認証コード・「お申し込みが入りました」・「反映済み」通知などは対象外）
- **本文形式**: プレーンテキストの「ラベル | 値」「◆ラベル | 値」を解析
  （`parseAsoviewReservation_` / `asvField_` / `asvDetail_`）
- **抽出項目**: お名前・電話番号・催行日・コース時間・アクティビティ・プラン名・
  参加人数（大人／小人を集計）・お子様の有無・宿泊先・備考・料金・集合場所・予約番号・管理URL
- **お客様のメールアドレスはメールに載らない**ため、`email:（アソビュー経由・記載なし）`
  と記録し、**自動返信の下書き・前日リマインドは作りません**（カレンダー登録のみ）。
  ※前日リマインドは宛先メールが空の予定を自動スキップするので、あそびゅー予約には送られません。
- **時間**: コースの時刻から 4 時間（時刻が取れなければ 11:00〜15:00）
- **二重登録防止**: フォーム予約と同じ `カレンダー登録済み` ラベルで管理
- メール書式が変わって抽出に失敗した場合は `parseAsoviewReservation_()` 内のラベル名を実際の
  メールに合わせて修正してください。

## アクティビティジャパン（activityjapan）予約の自動登録

**アクティビティジャパンの「即時確定予約通知」メール**も同じ `予約状況` カレンダーに
自動登録します（`processActivityJapan_`）。

- **対象**: **件名に「確定予約通知」を含み、本文に「アクティビティジャパン」を含む**メール
  （本来の送信元は `reserve-system@activityjapan.com`。転送メールでも拾えるよう件名＋本文で判定。
  オファー通知・メッセージ受信通知などは対象外）
- **本文形式**: プレーンテキストの「ラベル：値」（**全角コロン**区切り）。転送メールの
  行頭「> 」引用符も自動除去（`parseActivityJapanReservation_` / `ajField_`）
- **時刻**: 独立項目が無いため、**プラン名末尾の「（HH:MM）」**から取得
- **抽出項目**: お名前・電話番号・催行日・時刻・プラン名・参加人数（大人／子供を集計）・
  お子様の有無・宿泊先（備考内のホテル名）・備考（お客様メモ）・料金・予約番号・管理URL
- **お客様のメールアドレスはメールに載らない**ため `email:（アクティビティジャパン経由・記載なし）`
  と記録し、**自動返信の下書き・前日リマインドは作りません**（カレンダー登録のみ）
- **二重登録防止**: フォーム予約と同じ `カレンダー登録済み` ラベルで管理
- メール書式が変わって抽出に失敗した場合は `parseActivityJapanReservation_()` を実際の
  メールに合わせて修正してください。

## じゃらん（jalan / ACTIVITY BOARD）予約の自動登録

**じゃらん（遊び・体験予約）の事業者向け「予約確定通知」メール**も同じ `予約状況`
カレンダーに自動登録します（`processJalan_`）。

- **対象**: **件名に「予約確定通知」を含み、本文に「じゃらん」または「activityboard」を含む**メール
  （本来の送信元は `reservation@activityboard.jp` ＝事業者管理画面 ACTIVITY BOARD からの通知。
  転送メールでも拾えるよう件名＋本文で判定）
- **★重要**: お客様に届く控えメール「**ご予約確定のお知らせ**」（`info01-asb@jalan.net`）ではなく、
  **事業者に届く「予約確定通知」の方**を対象にしている。控えメールには実施会社（自店）の
  電話番号が載る等で紛らわしいため使わない
- **本文形式**: プレーンテキストの「ラベル：値」（全角コロン区切り）。転送の「> 」も除去
- **日時**: 「利用日時：YYYY/MM/DD(曜) HH:MM〜…」の**開始時刻**から取得（スラッシュ日付）
- **宿泊先**: 「予約者からの回答：」（回答が次行にある場合も対応）から取得
- **抽出項目**: お名前・お客様メール・電話番号・利用日時・プラン名・参加人数（大人／子供内訳）・
  お子様の有無・宿泊先・料金・当日緊急連絡先・予約番号
- このメールには**お客様のメールアドレスも載る**ため、`email:` ラベルで記録し、
  他OTAと違って**前日リマインドの送信対象になる**（返信下書きの自動作成は行わない）
- **二重登録防止**: フォーム予約と同じ `カレンダー登録済み` ラベルで管理

## 予約サイト共通のしくみ

`processMailToCalendar`（5分おきトリガー）が、自社フォームに続けて
**あそびゅー → アクティビティジャパン → じゃらん** の各処理を毎回まとめて実行します。
どのサイトも同じ `予約状況` カレンダー・同じ `カレンダー登録済み` ラベルを使い、
件名＋送信元／本文で対象を判定するため相互に混ざりません。前日リマインドは
**サイトを問わず、予定の説明欄に `email:` として実際のメールアドレスが記載されている
予約すべてに送信**されます（あそびゅー・アクティビティジャパンはお客様メールアドレスが
メールに載らないため対象外、じゃらんはメールアドレスが載るため対象）。
自動返信の下書き作成のみ自社フォーム予約限定です。

## 再登録したい場合

対象メールから `カレンダー登録済み` ラベルを外すと、次回実行時に再登録されます。

## 補足

- FormSubmit のメール書式（表の項目名）が変わると抽出に失敗します。その場合は
  `Code.gs` の `parseReservation_()` 内のラベル名を実際のメールに合わせて修正してください。
- 件名の `【】` の中身（ツアー名）は変わっても動作します（「予約」を含むかどうかだけで判定）。
